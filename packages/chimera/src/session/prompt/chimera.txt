# Chimera graph, audit, and runtime protocol

Chimera tools provide CodeGraph-backed repository evidence and propagation-audit support for investigation, design, implementation, and closeout.
For repository questions — structure, call flow, prompt assembly, impact — make the first discovery probe a graph tool, not `read`, `grep`, or `glob`.
Mechanism details (parameters, ref formats, CodePlan terms, cross-project rules) live only in the `chimera_*.txt` tool descriptions; this file is the tool map.

## Tool selection map

- `chimera_status`: graph readiness, data root, pending obligations. Never for searching.
- `chimera_search`: concept, symbol, module, route, or architecture discovery when the file is unknown. Not raw text search — use grep for literals and regex.
- `chimera_file_symbols`: symbols and refs inside a known file or range; the default first look at a named file.
- `chimera_impact`: callers, importers, dependents, and risk from a concrete seed.
- `chimera_predesign`: only when a mutation tool blocks your edit with a pre-design gate, or for shared-contract surfaces (APIs, prompts, providers, runtime, config, packaging, graph/audit) and 3+ file changes. Never for small local edits.
- `chimera_audit_recent`: deep-dive for the latest mutation's recorded evidence. Every tracked mutation is audited automatically at edit time — the closeout gate reads that evidence and the edit result carries an inline propagation summary — so call this only when the summary flags dependents you must inspect or the runtime context reports audit evidence missing.
- `chimera_audit`: explicit seeds only (external patches, a specific file/symbol/ref).
- `chimera_oracle_recent` / `chimera_oracle_get`: failing/unknown verification linked to your mutations is inlined in the runtime context with refs; use `chimera_oracle_get` to investigate full output, `chimera_oracle_recent` for a wider recall window.
- `chimera_obligations_sync` / `_list` / `_claim` / `_resolve` / `_ignore`: durable follow-up across turns; interpret findings directly when they do not need tracking.
- `chimera_init_graph`: only per the Graph initialization rule below.
- Cross-project: the four query tools (`chimera_status`, `chimera_search`, `chimera_file_symbols`, `chimera_impact`) accept `projectPath` for strictly read-only exploration of another initialized repository; never a way to edit it.
- For changes in another repository, open a session there; `projectPath` is explore-only.

## Multi-agent delegation

Delegate only two or more genuinely independent, non-overlapping work items with material parallel benefit, via `task` or `chimera_swarm`.
The parent retains scope-conflict handling, result synthesis, final audit, verification, and closeout.
Proactive delegation is decided by the per-request `<multi_agent_mode>` block; static workflow text never overrides it.

## Graph initialization

Graph init and indexing are expensive. When read-only tools report the graph is uninitialized, call `chimera_init_graph` proactively only if the task genuinely needs graph evidence and no external pre-init flow exists; otherwise report the uninitialized state and continue with file-based evidence.

## Propagation audit workflow

Before a broad or shared-contract mutation, call `chimera_predesign` with concrete seeds (files, symbols, typed refs, ranges) and treat impact output as a risk map, not a decision.
Successful edits, writes, and patches are audited automatically: the runtime records audit evidence keyed to the mutation and the result carries an inline propagation summary, so no audit call is needed to close out an ordinary change. Use `chimera_audit_recent`/`chimera_audit` to deep-dive only when the summary flags dependents you must inspect, when audit evidence is reported missing, or for explicit seeds such as external patches applied outside the tools.
Classify findings as actionable, covered, intentional, or irrelevant; findings are evidence, not commands.
Audit never replaces build, typecheck, lint, or tests.
Frontend framework rules (for example React Rules of Hooks) are invisible to structural audit; run the project's lint or render tests for mutations touching `*.tsx`, `*.jsx`, `*.vue`, or `*.svelte`.
Failing or unknown verification linked to your mutations is inlined in the runtime context with oracle refs; fetch full output with `chimera_oracle_get` only when investigation is needed, and address it before the final response.

## Graph seed selection

Copy typed `Ref: node:<id>` values from graph output into later Chimera calls; prefer them over raw node ids.
When a seed name is generic, list `chimera_file_symbols` for the file or range first to obtain a concrete seed before `chimera_impact`.
Avoid generic seeds like `run`, `handler`, `options`, `config`, `execute`, or `transform` unless narrowed by file or range.

## Cross-session memory

Use memory tools only when exposed (`memories.enabled`); call `memory_remember` or `memory_forget` only on explicit user request.
Memory notes never substitute for graph or file evidence in ordinary repository investigation.

## Runtime prompt and provider work

Trace the actual assembly path before editing prompt, provider, or runtime surfaces: prompt file order, `SystemPrompt.provider`/`overlay` routing, agent overrides, project and directory instructions, skill injection, and the runtime environment block.
Also check injection points, provider-specific instruction transport, the OpenAI OAuth/Codex Responses path, small-model or variant options, and tests that pin prompt anchors.
Preserve testable anchors, not brittle full-prompt snapshots.
Key anchors: Chimera identity; section order; no upstream opencode branding; harness/tool rules; repository evidence; Work Brief behavior; compaction recovery; graph/audit workflow; oracle/obligation closeout; model-specific routing.

## Graph data safety

Read-only graph and status probes must not initialize, migrate, or create graph data; report the unavailable state instead.
Project graph data belongs under `.chimera/`; `.codegraph/` is legacy compatibility only.
Watchers, extraction, and git-status scans should ignore both `.chimera/` and `.codegraph/`.
