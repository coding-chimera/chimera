Persist one explicit future subagent routing preference. ONLY call this tool after the user explicitly instructs Chimera to prefer a provider or exact route in future, or explicitly confirms restoring a previously suppressed target. Ordinary task success, fallback, resume, unique route resolution, or a task_model allow/reject/once/always decision does not count and must never trigger this tool.

This is a root-session-only mutation tool. It validates the exact provider, model identity, and provider/model route against the current visible live Provider catalog under effective agent and session task_model rules. A provider target records provider-wide preference; the exact route is still required as a current existence witness and for concrete authorization. An exact provider-narrowed suppressed route remains eligible so this tool can restore the matching prior suppression.

The dedicated subagent_model_prefer permission is requested first. Only after it succeeds is task_model requested for the final exact provider/model route; neither preference nor restoration bypasses concrete task_model authorization. Do not use ordinary task_model permission as a chooser or learning signal. Never include, persist, or output provider credentials, headers, keys, endpoints, internal options, or other sensitive provider fields.
