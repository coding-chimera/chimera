Edits files using Hashline anchors from the Read tool.

Usage:
- Use your `Read` tool to get current `LINE#ID` anchors before editing existing file content. Anchored edits fail when a line's current text no longer matches the supplied hash.
- Read output prefixes text lines as `<line>#<hash>|<content>`. Use only the `LINE#ID` portion as `pos` / `end`. Everything after `|` is actual file content.
- The `lines` field must contain real file text, not diff text. Never include Hashline prefixes in `lines`; the tool strips common accidental prefixes, but you should not rely on that.
- String `lines` input treats one final newline as a split sentinel; array input preserves explicit trailing `""` entries for blank lines.
- Use `edits: [{ op: "replace" | "append" | "prepend", pos?, end?, lines }]`. `replace` requires `pos`; `end` extends the replaced range. `append` / `prepend` may omit anchors to insert at EOF/BOF or create a missing file.
- Multiple edits for the same file should be sent in one call. All anchors are validated against the same pre-edit snapshot and then applied bottom-up.
- ALWAYS prefer editing existing files in the codebase. NEVER write new files unless explicitly required.
- Only use emojis if the user explicitly requests it. Avoid adding emojis to files unless asked.
- Stale anchors self-heal: when an anchor no longer matches its line, the tool scans the file for a unique content match and relocates the anchor automatically, reporting the relocation in the output. Ambiguous or missing matches fail with the current `LINE#ID` anchors in the error, usable directly for retry.
- The edit will FAIL for overlapping ranges, empty anchored inserts, and no-op edits.
- Legacy `oldString` / `newString` / `replaceAll` parameters are not supported.
- The Chimera mutation gate runs only AFTER your full call is generated: a blocked call discards everything you composed. Before composing large or risky edits (shared contracts — APIs, prompts, providers, runtime, config, packaging, graph/audit — or changes spanning 3+ files), call `chimera_predesign` FIRST with intent and likely files/symbols.
- If a call is still blocked, the blocked result stashes your input under a replay key: satisfy the gate, then re-call this tool with `replay: "<key>"` to reuse the stashed input unchanged instead of regenerating it. Re-issue the full call only when the predesign evidence changes what you want to write.
- Successful mutations are audited automatically at edit time; read the inline propagation summary in the result and deep-dive with `chimera_audit_recent` only when it flags dependents you must inspect or audit evidence is reported missing.
