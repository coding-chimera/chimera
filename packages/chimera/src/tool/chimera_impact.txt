Analyze bounded file and symbol impact through Chimera's CodeGraph surface.

Use this tool when you need static graph evidence about callers, importers, file dependents, or impact radius for a known file, symbol, node id, or source range — typically before changing a shared API, prompt, config, route, or tool surface, or when a user asks what a change might break.

Do NOT use it as a replacement for tests, typecheck, build, or lint; it is structural evidence, not oracle verification. Skip it for raw text search (grep), when no concrete seed exists yet (`chimera_search` / `chimera_file_symbols` first), for post-mutation closeout (`chimera_audit_recent`), or for pre-edit gate evidence (`chimera_predesign`).

Seed selection:
- Pass at least one concrete, non-empty seed: `ref`, `nodeID`, `symbol`, or `filePath`. Blank seed strings are not a valid query and fail.
- Prefer `ref` copied exactly from a prior `Ref: node:<id>`; legacy `nodeID` only for an exact id without a typed ref.
- Use `filePath` for file-level dependents and importers; add `range` to seed from a known line range. Explicit `filePath` seeds are synced from the filesystem before resolution, even when untracked by git.
- Use `symbol` only when the name is specific enough; generic names like `run`, `handler`, or `options` may match unrelated symbols. For generic, duplicated, or file-local names, resolve via `chimera_file_symbols` first and pass the copied `ref`.

When no seed resolves, output lists the closest candidate symbols with refs; `- None found.` means the graph has no near match.

`projectPath`: optional path to another initialized Chimera project (or its subdirectory) for strictly read-only cross-project queries; never initializes or writes there. Seeds resolve against the target graph and `filePath` seeds are not filesystem-synced. See `chimera_status` for full cross-project rules.

After this tool:
- Treat output as risk and propagation evidence, not proof of correctness; interpret it in task context and run build/typecheck/lint/tests separately when correctness matters.
