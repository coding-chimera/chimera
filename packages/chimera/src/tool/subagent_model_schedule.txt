Inspect current cost-aware subagent model recommendations by workload before dispatching work.

Use this read-only tool when choosing a model for `task` or `chimera_swarm`, or when you need more recommendation detail than the compact runtime-context summary. Omit `workload` to inspect every current archetype, or pass one current workload name to narrow the result. Recommendations are built from the live permission-filtered provider catalog, explicit routing preferences, billing and quota feasibility, compact DeepSWE capability anchors with a shared reasoning-tier curve, model size classes (S/M/L/XL), local speed evidence (measured tokens-per-second blended over static size-class norms), and live Provider token pricing when available.

Effort is chosen per archetype `minQuality`: a candidate dispatches the lowest reasoning tier whose quality at that tier meets the threshold, so large anchored models pass at low tiers while smaller models climb; when no tier meets it, the highest eligible tier is used and the candidate is flagged unproven. Routes at or above the configured top-tier-disabled size class (default XL) drop their highest reasoning tier before selection, and archetypes may exclude routes above a maximum size class. Proven (anchored/curve, above threshold) candidates rank before unproven ones; an archetype whose recommendations contain zero proven candidates is marked `no-proven-candidate (unproven fallback)`.

This tool does not create child sessions, request authorization, mutate preferences, or grant permission. A recommendation is not authorization: the final concrete route still requires normal `task_model` handling when dispatched. Use `subagent_model_routes` instead when you need every concrete route for one exact model identity rather than workload ranking. Unknown workload names are rejected with the valid current names.
