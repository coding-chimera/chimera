Writes a file to the local filesystem.

Usage:
- This tool will overwrite the existing file if there is one at the provided path.
- If this is an existing file, you MUST use the Read tool first to read the file's contents. This tool will fail if you did not read the file first.
- Successful writes return a compact line count summary plus Hashline anchors for the new content (head and tail for large files). Follow-up anchored edits can use these anchors directly without re-reading the file.
- ALWAYS prefer editing existing files in the codebase. NEVER write new files unless explicitly required.
- NEVER proactively create documentation files (*.md) or README files. Only create documentation files if explicitly requested by the User.
- Only use emojis if the user explicitly requests it. Avoid writing emojis to files unless asked.
- The Chimera mutation gate runs only AFTER your full call is generated: a blocked call discards everything you composed. Before composing large or risky edits (shared contracts — APIs, prompts, providers, runtime, config, packaging, graph/audit — or changes spanning 3+ files), call `chimera_predesign` FIRST with intent and likely files/symbols.
- If a call is still blocked, the blocked result stashes your input under a replay key: satisfy the gate, then re-call this tool with `replay: "<key>"` to reuse the stashed input unchanged instead of regenerating it. Re-issue the full call only when the predesign evidence changes what you want to write.
- Successful mutations are audited automatically at edit time; read the inline propagation summary in the result and deep-dive with `chimera_audit_recent` only when it flags dependents you must inspect or audit evidence is reported missing.
