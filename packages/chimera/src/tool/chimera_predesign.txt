Record pre-edit Chimera evidence before a risky mutation.

Use this tool before `edit`, `write`, or `apply_patch` when the change is broad or risky: a mutation tool blocked your edit with the pre-design gate, the change touches shared-contract surfaces (APIs, prompts, providers, runtime, config, packaging, graph/audit), or it spans 3+ files. For small single-file or two-file local edits the mutation tools enforce pre-design evidence themselves via the gate — no preemptive call needed.

It performs bounded CodeGraph-backed impact discovery and records a run that mutation gates accept as fresh pre-edit evidence. A recorded run also declares to the project which files you intend to change, so prefer it for broad or multi-file work. State what and why in `intent`; add `files` to declare the exact mutation targets, or `symbols`/`refs` (prefer refs copied from `Ref: node:<id>`) when the risk is a graph seed. Impact discovery is the graph-dependent half: in a project whose graph is not initialized the run is recorded without impact evidence and the receipt says so — declare files there and claims still register.

Declared `files` also register advisory edit-intent claims for cross-session coordination — claims need no graph and are enforced even in projects that never ran `chimera graph init`: while your run is active, mutation tools of sessions from OTHER session families are blocked on those files, and your own mutations are blocked on files another family claimed earlier (first-come-first-served). Claims never block sessions in your own session family — conflicts are merged along the session parent chain, so a parent's claims do not gate its own subagents and vice versa. Claim lifecycle: released when you call `chimera_audit_recent` (explicit closeout — queued sessions wake immediately, and the unlock still runs on the degraded audit-less closeout when the graph is uninitialized), when your run completes with no background/subagent jobs your session family still owns running, or when your session is removed; the TTL is only a crash fallback — and queued sessions then receive an injected release notice. When the receipt reports a claim CONFLICT, do not fight the gate: work on non-conflicting files first and let the release notice resume the blocked part, or report the blockage to the user (or your parent agent) when nothing else remains.

This is not post-change verification: after a successful mutation run `chimera_audit_recent`, plus build/typecheck/lint/tests when correctness matters.

After this tool:
- Review the impact evidence, then retry the mutation if it was gate-blocked. A recorded run is pre-edit evidence, not proof the mutation is correct.
- On claim conflicts: proceed with non-conflicting work; the release notice arrives automatically — no polling or retry loops.

Automation setups that cannot call this tool (scripted drivers, CI agents) should deny it in the agent config — `tools.chimera_predesign = false` or an agent permission deny — which also auto-releases the mutation gate for that agent (the gate's deadlock guard). Edit-intent claim coordination still applies unchanged.
