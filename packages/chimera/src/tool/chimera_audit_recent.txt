Run the default Chimera propagation audit for the latest successful tool mutation.

Mutations tracked through `edit`, `write`, and `apply_patch` are audited automatically at edit time and the closeout gate reads that recorded evidence, so this tool is a deep-dive rather than a routine closeout step. Use it when the inline propagation summary flags dependents you must inspect, when the runtime context reports audit evidence missing, or when you need rendered findings for the latest mutation.

Do NOT pass file paths to this tool — it audits the latest mutation automatically; use `chimera_audit` for explicit files, symbols, or node ids. One audit per mutation batch is enough — do not also run chimera_audit on the same files afterwards; chimera_audit is for explicit seeds from other sources (external patches, a specific symbol).

Mechanics: findings are structural evidence, not commands or tracked obligations. Provenance files missing graph records are filesystem-synced before classification. Set `refresh` to false only when current graph state is known sufficient.

See chimera_audit description for the CodePlan atomic label glossary.

After this tool:
- Interpret findings in task context; intentional, irrelevant, duplicate, or temporary-cleanup findings can be skipped with a brief note. Use build/typecheck/lint/tests for oracle verification, and for frontend component files (`*.tsx`/`*.jsx`/`*.vue`/`*.svelte`) also run lint or render tests. Use `chimera_obligations_sync` only for tracked follow-up.
