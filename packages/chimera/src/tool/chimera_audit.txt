Run a first-pass Chimera propagation audit for explicit changed files, a changed symbol, a node id, or a source range.

Use this tool when the audit seed comes from another source — files changed by an external patch or shell command, or one specific symbol, route handler, or config surface — and you want non-persistent propagation findings.

Do NOT use it as the default post-mutation audit; use `chimera_audit_recent` after successful file mutations.

Mechanics: provide at least one seed (`files`, `filePath`, `symbol`, `ref`, or legacy `nodeID`), preferring `ref` copied from `Ref: node:<id>`; `range` requires `filePath`. Explicit file seeds are filesystem-synced before resolution, even when untracked by git. Findings are structural evidence, not commands or tracked obligations.

After this tool:
- Interpret findings in task context; intentional, irrelevant, or duplicate findings can be skipped with a brief note. Use build/typecheck/lint/tests for oracle verification; for frontend component files (`*.tsx`/`*.jsx`/`*.vue`/`*.svelte`) also run lint or render tests — framework-rule violations are invisible to structural audit. Use `chimera_obligations_sync` only for durable tracking.

CodePlan atomic label glossary (canonical; other tool descriptions refer here):
- Modification: `MMB` modified method body, `MMS` modified method signature, `MF` modified field, `MC` modified class declaration, `MCC` modified constructor signature, `MI` modified import/using statement.
- Addition: `AM` added method, `AF` added field, `AC` added class declaration, `ACC` added constructor, `AI` added import/using statement.
- Deletion: `DM` deleted method, `DF` deleted field, `DC` deleted class declaration, `DCC` deleted constructor, `DI` deleted import/using statement.
- `codeplan_atomic_label` selects relation-clause propagation rules; `statement_effect` summarizes method-body escape/effect; `relation_clause` + `impacted_block` are the clause and block chosen by the may-impact rule.
