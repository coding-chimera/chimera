Show Chimera and CodeGraph readiness for the current project, or for another project selected with `projectPath`.

Use this tool when you need to know whether the graph is ready, which revision and data root are active, or how many tracked obligations are pending.

Do not call it as a warm-up before other graph tools — query tools report graph readiness themselves, and the runtime context block already shows the snapshot. Do not use it to search symbols or audit propagation.

Read-only probe: never initializes, migrates, or creates graph data. `refresh=false` only when stale state is acceptable for a lightweight check. Ready status reports `missingFiles`; a positive count means symbols may be missing until a refresh reconciles them.

Cross-project `projectPath` rules (canonical for all graph tools): the path may target another Chimera project or a subdirectory inside it, walk-up resolved to the nearest initialized graph root (`.chimera/` or compatible legacy `.codegraph/`); a path resolving to the current project root equals omitting it. Cross-project access is strictly read-only: nothing is initialized, migrated, synced, watched, written, or recorded in the target and `refresh` is ignored; output is labeled `Project: <resolved root> (cross-project, read-only)`. An uninitialized target returns a structured error — tell the user to run `chimera graph init` then `chimera graph index` there themselves (large repos take a long time); never initialize another project's graph or edit its files from this session. A target schema older than this binary expects reports `needsMigration: true` with `schemaVersion`/`requiredVersion`; read-only surfaces never migrate — tell the user to run `chimera graph index` there.

After this tool:
- If obligations are pending during closeout, list or resolve them first; if the current graph is uninitialized, call `chimera_init_graph`.
